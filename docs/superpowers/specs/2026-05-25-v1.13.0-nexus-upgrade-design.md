## Pillar 1: Hardening & Security Fixes

### 1.1 Security: Gemini API Key Header Migration

**Files**: `packages/core/src/services/embedding.ts`, `packages/core/src/services/repair.ts`

**Problem**: API key passed as URL query parameter (`?key=${apiKey}`), leaking into server logs, proxy logs, and network intermediaries.

**Solution**: Replace URL query parameter with `x-goog-api-key` HTTP header on all Gemini API calls.

**Before**:
```typescript
const url = `https://generativelanguage.googleapis.com/v1/models/${model}:embedContent?key=${this.apiKey}`;
const response = await fetch(url, { method: 'POST', body: JSON.stringify(payload) });
```

**After**:
```typescript
const url = `https://generativelanguage.googleapis.com/v1/models/${model}:embedContent`;
const response = await fetch(url, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json', 'x-goog-api-key': this.apiKey },
  body: JSON.stringify(payload),
});
```

Apply same pattern in `repair.ts` for the Gemini content generation endpoint.

### 1.2 Security: LIKE Wildcard Injection Fix

**File**: `packages/core/src/database/access.ts`

**Problem**: User-controlled `pathFilter` passed directly into LIKE clause without escaping `%` and `_` metacharacters.

**Solution**: Create a `escapeLikePattern(input: string): string` utility that escapes `%`, `_`, and the escape character itself. Use `LIKE ? ESCAPE '\'` in the query.

```typescript
function escapeLikePattern(input: string): string {
  return input.replace(/[%_\\]/g, (ch) => `\\${ch}`);
}
```

### 1.3 Performance: Embedding Model Pre-Warm

**File**: `packages/core/src/services/embedding.ts`

**Problem**: First search blocks for seconds while the transformer model loads lazily.

**Solution**: Add a `warmup()` method to `TransformersProvider` that triggers model loading. Call it from the DI container's new `start()` lifecycle (Pillar 3). If warmup fails (no model available), log a warning and fall back to lazy load.

```typescript
async warmup(): Promise<void> {
  try {
    await this.getOrLoadModel();
    this.logger.info('Embedding model pre-warmed');
  } catch (err) {
    this.logger.warn('Embedding warmup failed, will lazy-load on first use', err);
  }
}
```

### 1.4 Performance: Selective Column Fetch in getAll()

**File**: `packages/core/src/database/documents.ts`

**Problem**: `SELECT * FROM documents` loads content blobs into memory during reindex mtime comparison.

**Solution**: Replace with `SELECT path, mtime FROM documents` when called for reindex purposes. Add an optional `columns` parameter or create a separate `getAllMetadata()` method.

```typescript
getAllMetadata(): Array<{ path: string; mtime: number }> {
  return this.db.prepare('SELECT path, mtime FROM documents').all() as Array<{ path: string; mtime: number }>;
}
```

Update `reindex()` callers to use this method instead of `getAll()`.

### 1.5 Performance: Bounded Recursive Graph CTE

**File**: `packages/core/src/database/graph.ts`

**Problem**: Recursive CTE in `getAffinities()` can expand exponentially on dense graphs with no result limit.

**Solution**: Add `LIMIT 100` to the outer SELECT. Accept an optional `maxResults` parameter (default 100).

```typescript
getAffinities(nodeId: string, minWeight = 0.1, maxResults = 100): Affinity[] {
  const stmt = this.db.prepare(`
    WITH RECURSIVE walk(target, weight, depth) AS (
      SELECT target, weight, 1 FROM edges WHERE source = ? AND weight >= ?
      UNION ALL
      SELECT e.target, w.weight * e.weight, w.depth + 1
      FROM walk w JOIN edges e ON e.source = w.target
      WHERE w.depth < 3 AND w.weight * e.weight >= ?
    )
    SELECT target, MAX(weight) as weight FROM walk GROUP BY target ORDER BY weight DESC LIMIT ?
  `);
  return stmt.all(nodeId, minWeight, minWeight, maxResults) as Affinity[];
}
```

### 1.6 Resilience: HTTP Body Stream Accumulation

**File**: `workspace-mcp/src/server-http.ts`

**Problem**: Body size enforcement relies solely on `Content-Length` header which can be omitted or falsified.

**Solution**: Stream-accumulate the request body with a hard byte counter. Destroy the socket immediately if accumulated bytes exceed `MAX_BODY_BYTES`.

```typescript
function collectBody(req: IncomingMessage, maxBytes: number): Promise<Buffer> {
  return new Promise((resolve, reject) => {
    const chunks: Buffer[] = [];
    let totalBytes = 0;
    req.on('data', (chunk: Buffer) => {
      totalBytes += chunk.length;
      if (totalBytes > maxBytes) {
        req.destroy();
        reject(new Error('Request body too large'));
        return;
      }
      chunks.push(chunk);
    });
    req.on('end', () => resolve(Buffer.concat(chunks)));
    req.on('error', reject);
  });
}
```

### 1.7 Resilience: Vector Cache Key Includes Provider

**File**: `packages/core/src/database/vectors.ts`

**Problem**: Cache key based only on query text. Model swap serves stale embeddings until TTL expires.

**Solution**: Include provider identifier in cache key: `${providerName}:${queryText}`.

### 3.4 Capability-Based Task Routing

**Files**: `packages/core/src/orchestration/task-graph.ts`, `packages/core/src/orchestration/scheduler.ts`

**Problem**: Scheduler picks least-loaded agent regardless of capabilities. Mismatched assignments fail.

**Solution**:

1. Add `requiredCapabilities` to `CreateTaskOpts`:
```typescript
interface CreateTaskOpts {
  id: string;
  dependencies?: string[];
  priority?: number;  // NEW (P2 improvement)
  requiredCapabilities?: string[];  // NEW
}
```

2. Scheduler filters by capability before load-balancing:
```typescript
assignNext(): { taskId: string; agentId: string } | null {
  const ready = this.taskGraph.getReadyTasks();
  const sorted = ready.sort((a, b) => (b.priority ?? 0) - (a.priority ?? 0));

  for (const task of sorted) {
    const candidates = task.requiredCapabilities?.length
      ? this.registry.findByCapability(task.requiredCapabilities)
      : this.registry.getAvailable();

    const leastLoaded = candidates.sort((a, b) => a.load - b.load)[0];
    if (leastLoaded) {
      return { taskId: task.id, agentId: leastLoaded.id };
    }
  }
  return null;
}
```

### 3.5 DI Container Lifecycle

**File**: `packages/core/src/container/container.ts`

**Problem**: No coordinated startup/shutdown. Resources leak on process exit.

**Solution**: Add `Lifecycle` interface and container orchestration:

```typescript
interface Disposable {
  dispose(): Promise<void> | void;
}

interface Warmable {
  warmup(): Promise<void> | void;
}

class ServiceContainer {
  async start(): Promise<void> {
    for (const service of this.getAll()) {
      if (isWarmable(service)) await service.warmup();
    }
    this.started = true;
  }

  async stop(): Promise<void> {
    for (const service of this.getAll().reverse()) {
      if (isDisposable(service)) await service.dispose();
    }
    this.started = false;
  }
}
```

### 3.7 Configurable Retry with Exponential Backoff

**File**: `packages/core/src/orchestration/task-graph.ts`

**Problem**: Hardcoded `maxRetries: 2` with no backoff.

**Solution**:
```typescript
interface RetryConfig {
  maxRetries: number;       // default: 3
  baseDelayMs: number;      // default: 1000
  maxDelayMs: number;       // default: 30000
  backoffMultiplier: number; // default: 2
}

fail(taskId: string, error: string): 'retrying' | 'permanent_failure' {
  const task = this.nodes.get(taskId);
  if (task.retryCount < task.retryConfig.maxRetries) {
    task.retryCount++;
    task.status = 'pending';
    task.nextRetryAt = Date.now() + Math.min(
      task.retryConfig.baseDelayMs * (task.retryConfig.backoffMultiplier ** task.retryCount),
      task.retryConfig.maxDelayMs
    );
    this.eventBus.emit('task.retried', { taskId, attempt: task.retryCount, nextRetryAt: task.nextRetryAt });
    return 'retrying';
  }
  task.status = 'failed';
  this.eventBus.emit('task.failed', { taskId, error, attempts: task.retryCount });
  return 'permanent_failure';
}
```

## Risk Mitigation

| Risk | Mitigation |
|------|-----------|
| Schema migration breaks existing databases | Add migration with version check; only CREATE new tables, never ALTER existing |
| Embedding warmup slows startup for quick commands | Make warmup async with timeout (5s max); commands that don't need embeddings don't wait |
| MCP resource subscriptions leak memory | Track subscriptions per session; clean up on disconnect |
| 27 new test files take excessive implementation time | Use shared helpers; test structure over behavior for simpler modules |
| CLI global flags break existing scripts | Flags are opt-in; default behavior unchanged |

## Non-Goals (Deferred to v1.14.0+)

- MCP Sampling (server-initiated LLM calls)
- MCP Elicitation (user input requests)
- MCP Tasks (durable execution)
- MCP Roots support
- Distributed rate limiting (Redis-backed)
- OpenTelemetry export (just internal metrics for now)
- Property-based testing (fast-check)
- CLI plugin/extension system
- CLI interactive REPL mode
- Multi-hop graph affinities (BFS with decay)
- Audit log pagination/incremental verification
